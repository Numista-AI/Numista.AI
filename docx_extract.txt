For a legal-grade System of Record this is unacceptable. The next plan must show the decision rewritten so that a non-null, non-anonymous Firebase user **always** forces the real Firestore stream and clears the flag; the flag may only be consulted when there is no real user. Clearing the flag is necessary but not sufficient.
2. **State machine for Browse Demo / real user / anonymous guest is undefined.** The plan clears the flag on both `_signIn` and `_signInAsGuest`. GuestSeedService appears designed to support anonymous/guest seeding. Next plan must contain an explicit matrix (or short state machine) of allowed combinations and the exact behaviour for each. Ambiguity here will re-introduce the same class of leak.
