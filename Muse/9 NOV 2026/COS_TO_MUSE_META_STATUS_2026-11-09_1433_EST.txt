5. Our proposed measurement design (plan v6, NOT implemented)
-------------------------------------------------------------
- Main app: the Numista Flutter app never loads Meta code.
- Consent: an optional checkbox, unchecked by default. Global Privacy Control (GPC) is
  respected.
- Pixel: after a real sign-up, the user goes to a separate completion page on its own
  address (for example go.numista.ai, which isn't set up in the code we inspected). That
  page tries once to send a CompleteRegistration event with no parameters. Firing and
  delivery aren't guaranteed. No PageView, no advanced matching, no purchase events, no
  Conversions API and no customer data. 'No parameters' doesn't mean anonymous or data-free.
  The browser's requests to Meta can still expose request details (such as IP address,
  browser info and page address) and cookies, depending on the Meta script, its settings and
  consent. We haven't observed what the script actually collects; please check the current
  defaults (Q6). Consent and cookie decisions are still open.
- Internal marker: a yes/no in Numista's own database for each new account. It is 'yes' if
  the browser's last ad-click landing (one carrying fbclid) in the past 7 days was tagged
  utm_campaign=numista_tg26. It's a same-browser guess, not proof of ad attribution: it
  misses other devices and blocked storage, and it counts shared links. The marker sends
  Meta nothing. Using the marker alone gives an internal count; it is not Meta conversion
  reporting.
- Neither part guarantees that Meta receives, attributes or optimizes on anything.
- Two independent reviews passed the plan text before today's code findings, scoring 97/100
  each. Those scores don't cover code verification, Meta approval, deployment or the new
  findings.

NOTE: Status now: implementation is NO-GO, even switched off by default. The repeated
