FROM META'S OFFICIAL HELP CENTER:
  - Learning phase: an ad set usually exits learning after about 50 results
    (optimization events) in the week after its last significant edit.
    "About the learning phase":
    https://www.facebook.com/business/help/112167992830700
  - Learning limited: if an ad set is unlikely to get ~50 optimization
    events in a week, it is flagged Learning Limited — not a penalty, but
    delivery can't optimize properly. Causes include an infrequent
    optimization event and low budget:
    https://www.facebook.com/business/help/269269737396981
  - Landing page views: counted when the page loads after an ad click,
    tracked via a Meta Pixel on the page OR via Meta's in-app browser; so
    partial LPV reporting can exist without a pixel, but the pixel is the
    reliable measurement path.
    https://www.facebook.com/business/help/361750134220832
    https://www.facebook.com/business/help/417293491972212
  - Limited Data Use (LDU): a flag sent with events via data processing
    options; when set, Meta processes flagged data as a service
    provider/processor under state-specific terms. Available for the Meta
    Pixel in CA, CO, CT, DE, FL, MD, MN, MT, NE, NH, NJ, OR, RI, TX. Meta
    states the decision of if/when to send the flag is the business's, "with
    the advice of your legal counsel"; one stated trigger is a Global
    Privacy Control opt-out signal (CA/CO). LDU limits retargeting and
    measurement.
    https://www.facebook.com/business/help/1151133471911882
  - Domain verification: verifying the ROOT domain also gives control of
    all subdomains; three methods (meta tag, HTML file, DNS TXT); the meta
    tag must be in the page's STATIC HTML because Meta's crawler does not
    run JavaScript. Its stated purpose today is ownership and control of
    link editing/permissions for your content and ads.
    https://www.facebook.com/business/help/286768115176155
    https://www.facebook.com/business/help/340070217802345

Q4. SIGN-UP OPTIMIZATION — REQUIREMENTS AND A CHALLENGE TO YOUR DESIGN.
    Requirements as Meta runs them today:
      - Objective: Sales (website conversions) — Leads is for lead forms /
        CRM-style flows; for website sign-ups, use Sales with conversion
        location "Website."
      - Conversion dataset: the Pixel dataset selected at ad-set level, and
        it must be connected to the ad account (done: C1/C2).
      - Conversion event: CompleteRegistration must be received by Meta and
        show as an active event in Events Manager before it can be chosen;
        in practice, fire it in testing first so it registers.
      - Domain: the old "8 prioritized events / Aggregated Events"
        configuration no longer applies. Domain verification is about
        ownership/link control (see (b)); it is not the gate it was in the
        iOS-14 era, but verifying numista.ai is still recommended and,
        importantly for your design, verifying the ROOT domain covers
        subdomains such as a completion page host.
      - Volume/learning: ~50 CompleteRegistration events per ad set per
        week to exit learning (see (b)); below that, expect Learning
        Limited for the whole flight.
    Would ONE parameterless CompleteRegistration from a separate completion
    page "count"? Technically the event is a valid standard event with no
    required parameters, and a verified root domain covers the subdomain.
    BUT your design has a real attribution hole you should weigh:
      * The Pixel never loads on the landing page, so no _fbp cookie and no
        fbclid capture happen when the ad click lands. When the user later
        arrives at the completion page directly (an in-app redirect after
        sign-up), the URL carries no fbclid, so the event can reach Meta
        with no click identifier tying it to the ad click. Meta may log the
        event yet be unable to attribute it to the campaign — which is the
        very signal optimization needs.
      * Volume: at $625 over 7 days for a brand-new product, ~50
        attributed sign-ups in a week is unlikely, so even a perfectly
        wired event probably leaves the ad set Learning Limited.
      * Reliability: "tries once" firing with no PageView also means no
        landing-page-view optimization fallback and no website retargeting
        audiences can be built.
    Verdict: the design can produce a countable event; it does NOT
    reliably support a sign-up-optimization objective. If Eric wants Meta
    to optimize for sign-ups, the standard design (Pixel base code on the
    site, CompleteRegistration on sign-up success) is what Meta's system
    is built for. If privacy/design constraints rule that out, run the
    honest Traffic setup in Q3 instead of a Sales campaign fed by an
    unattributable event.
