### 2.6 Deep-Dive Audit of the 6 Pricing & Rounding Questions (`SAG_PACKET_NET-647_R2.6_20261031.md`)

1. **Q1 — Python `Decimal(str(line_total)) / Decimal(str(qty)) * 100` with `ROUND_HALF_UP`:**
   - For `64.97 / 2`: `Decimal('64.97') / Decimal('2') * Decimal('100') = Decimal('3248.5')`, and `.quantize(Decimal('1'), rounding=ROUND_HALF_UP)` yields exactly **`3249` cents (`$32.49`)**.
   - **Edge case note for EXECUTE:** In Python 3, `str(float)` uses David Gay's shortest-representation algorithm (`str(64.97) == '64.97'`), which is safe for 2-decimal currency floats parsed from JSON, or better yet, `Decimal(f"{float(raw_line_total):.2f}")` guarantees exact 2-decimal string normalization even if an upstream float expression accumulated binary noise prior to conversion.
2. **Q2 — `unit_cost_cents` (`int`) Canonical vs. `unit_cost` (`float`) Display Copy:**
   - Storing `unit_cost_cents: 3249` (integer) as the primary canonical field alongside `unit_cost: 32.49` (float) is sound and backward-compatible. In §4.1 (`lines 123–124`), `review_hub_screen.dart` checks `if (data['unit_cost_cents'] != null)` first and only falls back to `formatCurrency(data['unit_cost'])` or `formatCurrency(data['line_total'] / cleanQty)` for legacy pre-backfill documents.
3. **Q3 — Dart `formatCurrency(num amount)` (`toStringAsFixed(4)` + 3rd-Decimal Half-Up):**
   - Because IEEE-754 `64.97 / 2` is `32.48499999999999943157`, `(64.97 / 2).toStringAsFixed(4)` rounds at the 4th decimal place (`9 >= 5`) to `'32.4850'`. Then `frac.substring(2, 3)` is `'5' >= 5`, which increments `3248` to **`3249` cents (`'32.49'`)**.
   - Verified across all 4 test cases: `32.485 -> '32.49'`, `2.44 -> '2.44'`, `84.50 -> '84.50'`, `100.005 -> '100.01'`. (Non-blocking guard for EXECUTE: if `amount < 0` is ever passed, operate on `amount.abs()` and prefix `'-'`.)
