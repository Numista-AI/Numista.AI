### Item 1 (#6): Per-Unit Pricing on Rolls and Multi-QTY Lines

#### Root Cause
In [review_hub_screen.dart](file:///c:/Users/ericd/Documents/MyVertexProject/numista_mobile/lib/screens/review_hub_screen.dart#L1980-L1990):
```dart
final rawCost = data['Purchase Cost'] ?? data['Cost'];
final baseCostStr = rawCost != null
    ? (rawCost is num ? '\$${rawCost.toStringAsFixed(2)}' : rawCost.toString())
    : 'N/A';
final qtyVal = data['Quantity'];
final cleanQty = qtyVal != null ? int.tryParse(qtyVal.toString()) ?? 1 : 1;
final costStr = (cleanQty > 1 && baseCostStr != 'N/A')
    ? '$baseCostStr each'
    : baseCostStr;
```
For product `26SQRP` (2026 Semiquincentennial Presidential $1 25-Coin Roll), the invoice line total is `$61.00`, and quantity is extracted as `25`. In Firestore, `data['Cost']` = `61.00` and `data['Quantity']` = `25`.
Because line 1988 simply concatenated `'$baseCostStr each'` directly to the line total, the UI rendered `"$61.00 each"` rather than computing the unit price:
$$\text{Per-Unit Cost} = \frac{\text{Line Total}}{\text{Quantity}} = \frac{\$61.00}{25} = \$2.44\text{ each}$$

Similarly, for multi-quantity items like American Innovation (QTY 2, $64.97 total), appending `" each"` without dividing by quantity results in displaying the extended line total as the per-unit price.

#### Surgical Fix
1. **Frontend Calculation & Display** ([review_hub_screen.dart](file:///c:/Users/ericd/Documents/MyVertexProject/numista_mobile/lib/screens/review_hub_screen.dart#L1980-L1995)):
   - Parse numeric cost from `rawCost` (stripping `$`, `,`, and whitespace).
   - If `cleanQty > 1` and numeric cost is available:
     - Check whether the stored cost represents the line total or an already-divided unit cost. If `data['unit_cost']` is explicitly present, use it. Otherwise, compute:
       `unitCost = numericCost / cleanQty`
       `totalCost = numericCost`
     - Render formatted string: `"\$${unitCost.toStringAsFixed(2)} each (\$${totalCost.toStringAsFixed(2)} total)"` or `"\$${unitCost.toStringAsFixed(2)} each"`.
2. **Backend Normalization** ([numista_backend/main.py](file:///c:/Users/ericd/Documents/MyVertexProject/numista_backend/main.py#L7495-L7510)):
   - When storing invoice items in `normalize_and_validate_receipt`, if an item has `qty > 1` and the invoice gives a line total, persist both:
     `"Cost": landed_cost_basis / item_qty` (canonical per-unit cost basis)
     `"line_total": landed_cost_basis`
     `"unit_cost": landed_cost_basis / item_qty`
     `"Quantity": item_qty`

#### Test
- **Unit Test**: In `numista_backend/tests/test_us_mint_invoice_enrichment.py` and `numista_mobile/test/review_hub_pricing_test.dart`:
  - Test 1: `26SQRP` roll with total `$61.00` and `Quantity: 25` -> per-unit cost asserts to `$2.44`, display text asserts to `"$2.44 each"`.
  - Test 2: `American Innovation` line with total `$64.97` and `Quantity: 2` -> per-unit cost asserts to `$32.49`, display text asserts to `"$32.49 each"`.
  - Test 3: Single item (`Quantity: 1`, `$173.00`) -> asserts to `"$173.00"`.
  - Test 4: Morgan x2 (`$169.00 each`, unit cost stored) -> asserts to `"$169.00 each"`.

### Item 2 (#9): Set Location Save Error & Persistence

#### Root Cause
In [review_hub_screen.dart](file:///c:/Users/ericd/Documents/MyVertexProject/numista_mobile/lib/screens/review_hub_screen.dart#L1054-L1069):
```dart
await FirebaseFirestore.instance
    .collection('users')
    .doc(user.email!)
    .collection('review_queue')
    .doc(docId)
    .update(updates);
```
1. **Direct Web Client Write Issue**: On Flutter Web, client-side direct writes to Firestore subcollections rely on `FirebaseAuth.instance.currentUser.email`. When email casing differs, or if the client document state is desynced, Firestore throws a `FirebaseException`. `NumistaErrorHelper.toUserFriendly(e)` translates this exception to `"An unexpected error occurred. Please try again."`.
2. **Backend Whitelist Restriction**: All other review mutations (Commit, Delete, Break Up Set) run through the backend API via `HttpAuthClient`. The backend `/api/review/bulk_update` endpoint ([main.py](file:///c:/Users/ericd/Documents/MyVertexProject/numista_backend/main.py#L3777-L3780)) had an overly restrictive field check:
   ```python
   allowed_keys = {"storage_location", "condition", "notes", "status"}
   for k in (request.updates or {}).keys():
       if k not in allowed_keys:
           raise HTTPException(status_code=400, detail=f"Invalid update field: {k}")
   ```
   When the edit dialog submitted `"Storage Location"` (Title Case), the backend rejected the update with HTTP 400.

#### Surgical Fix
1. **Backend Endpoint Expansion** ([main.py](file:///c:/Users/ericd/Documents/MyVertexProject/numista_backend/main.py#L3775-L3795)):
   - Expand `allowed_keys` in `/api/review/bulk_update` to support both Title Case and snake_case coin fields:
     `{"storage_location", "Storage Location", "condition", "Condition", "notes", "Personal Notes", "status", "Year", "Mint Mark", "Denomination", "Country", "Program/Series", "Strike Type", "Metal Content", "Purchase Cost", "Cost", "Purchase Date", "Retailer/Website", "Retailer Invoice #", "Retailer Item No.", "Quantity", "qty", "Variety", "Theme/Subject", "allocated_fee", "fee"}`.
   - Normalize keys so both `"Storage Location"` and `"storage_location"` update the Firestore document reliably.
2. **Frontend Robust Update** ([review_hub_screen.dart](file:///c:/Users/ericd/Documents/MyVertexProject/numista_mobile/lib/screens/review_hub_screen.dart#L1054-L1070)):
   - Call `/api/review/bulk_update` via `HttpAuthClient.post` with the user's authenticated token.
   - If the backend call succeeds, reflect updates immediately in local state.
   - Maintain client fallback using `SetOptions(merge: true)` with lowercase trimmed email.

#### Test
- **Pytest**: `numista_backend/tests/test_review_bulk_update.py`:
  - Test `/api/review/bulk_update` with `{"Storage Location": "Vault Safe Box A"}` on a review queue item -> asserts HTTP 200, Firestore doc contains `"Storage Location": "Vault Safe Box A"`.
- **Widget Test**: In `numista_mobile/test/review_hub_edit_dialog_test.dart`:
  - Mock edit dialog submission for location update -> asserts no error snackbar, location chip updates from `"+ Set Location"` to `"Vault Safe Box A"`.

// --- PROPOSED DROP-IN REPLACEMENT ---
final rawCost = data['Purchase Cost'] ?? data['Cost'];
double? numericCost;
if (rawCost is num) {
  numericCost = rawCost.toDouble();
} else if (rawCost != null) {
  final cleaned = rawCost.toString().replaceAll(r'$', '').replaceAll(',', '').trim();
  numericCost = double.tryParse(cleaned);
}

final qtyVal = data['Quantity'] ?? data['qty'];
final cleanQty = qtyVal != null ? int.tryParse(qtyVal.toString()) ?? 1 : 1;

String costStr;

    // If unit_cost is explicitly provided, use it; otherwise compute per-unit price = total / qty

    final double unitCost = (explicitUnitCost is num)
        ? explicitUnitCost.toDouble()
        : (numericCost / cleanQty);
    costStr = '\$${unitCost.toStringAsFixed(2)} each';
  } else {
    costStr = '\$${numericCost.toStringAsFixed(2)}';
  }
} else {
  costStr = rawCost?.toString() ?? 'N/A';
}
