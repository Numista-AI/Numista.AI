## Required fix (1, small, systemic - same class as V2 fix 2)
1. **The owner wildcard still covers subcollections the server trusts.** firestore.rules:106 says so itself: `// Subcollections the owner CAN read+write (wishlist, review_queue, morgan_proposals, etc.)`. :108-110 `match /users/{email}/{sub}/{docId} { allow read, write: if isOwner(email) && !(sub in [...])` does not exclude:
   - `morgan_proposals`: /api/morgan/confirm trusts these docs (morgan_routes.py:169 `user_prop_ref = db.collection("users").document(caller_email).collection("morgan_proposals").document(req.proposal_id)`, then :216 `target_email = prop_owner_email or caller_email` and :261 `new_coin_ref.set(snapshot)` via Admin SDK). A user can forge a proposal (any action and any fields, including is_demo) or reset `used` to replay one. That skips Gate-0 Confirm and the coin is_demo rule. It only affects their own account, but it is a real bypass.
   - `subaccounts`: the server enforces tier limits (subaccount_routes.py:69 `if tier == "free" and len(existing_docs) >= 1:`), but the client can write sub-account docs directly and skip the limit.
   - `subscription`: upgrade_beta_testers_to_estate.py:184 writes `collection('subscription').document('status')` (entitlement-style data). Nothing reads it yet, but it must not be client-writable.
   No Flutter code writes any of these three (I grepped lib/), so making them server-only breaks nothing. Fix: add `'morgan_proposals', 'subaccounts', 'subscription'` to BOTH exclusion lists (:110, :115) and give each an explicit `allow read: if isOwner(email); allow write: if false;` block. Also look at `transferred_coins` (Certificate of Transfer history, backend-written 8x, never by the client) and make it server-only unless Flutter needs to write it.
