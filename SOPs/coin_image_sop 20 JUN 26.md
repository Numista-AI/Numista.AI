# Numista.AI — Coin Image Standard Operating Procedure
*Version 1.0 — 2026-06-20*

---

## Overview

Numista.AI uses a **three-layer image system**:

| Layer | What it is | Where it lives |
|---|---|---|
| **Layer 1 — Personal Photos** | Photos you or a user uploaded for their specific coin | `gs://studio-9101802118-8c9a8.firebasestorage.app/users/{email}/coins/{coinId}/` |
| **Layer 2 — Reference Index** | Curated reference images for any coin of a given year/program | `coin_image_index` (Firestore) → URLs in GCS buckets |
| **Layer 3 — AI Generated** | Fallback images generated by Imagen when nothing else exists | `gs://numista-reference-library/reference_library/ai_generated/` |

The app always prefers Layer 1 (personal) over Layer 2 (reference) for each side independently. If you have a personal obverse but no reverse, it will show your photo + the reference reverse.

> **Tier system:** Lower number = higher priority. When multiple images exist for the same coin, the lowest-tier (highest quality) source wins in the index.

## Naming Convention

### Standard Format

```
{year}[_{mint}][_{subject}]_{program-slug}_{side}.{ext}
```

### Rules
- **Lowercase everything** except mint mark
- **Underscores** separate fields; **hyphens** separate words within a field
- **Mint mark** is uppercase: `P`, `D`, `S`, `W`, `CC`, `O` — omit if Philadelphia or no mark
- **Subject** only for series programs (State Quarters, Presidential Dollars, Women Quarters, ATB, American Innovation, Native American Dollar, Commemoratives)
- **Side**: always `obverse` or `reverse`
- **Extension**: prefer `.jpg`; `.png` and `.webp` are fine

## Workflow 1 — Adding Official/Reference Images Manually

**Use this when:** You have sourced a high-quality image from the US Mint, PCGS, NGC, or another trusted reference.

### Steps

1. **Name the file** using the naming convention above
2. **Upload to the correct GCS folder** based on source quality:
   - US Mint official → `gs://numista-reference-library/reference_library/us_mint/`
   - Other curated → `gs://numista-reference-library/reference_library/bulk_programs/`
3. **Update the index** — run in the backend directory:
   ```powershell
   .venv\Scripts\python.exe _scripts\build_image_index.py
   ```
   *(No `--wipe` needed — uses merge, so existing entries are preserved)*
4. **Verify** — check the coin in the app (hard refresh: `Ctrl+Shift+R`)

## Workflow 2 — Contribution Folder (Batch Add)

**Use this when:** You have a batch of images from an external source (US Mint downloads, exhibition scans, etc.) and want to add them with proper attribution.

### Steps

1. **Drop images into the contribution folder:**
   ```
   C:\Users\ericd\Documents\MyVertexProject\new_coin_images\
   ```
2. **Edit `MANIFEST.json`** in that folder — fill in attribution, license, and per-image metadata
3. **Ingest and index** in one command:
   ```powershell
   .venv\Scripts\python.exe _scripts\build_image_index.py --ingest-contributions
   ```
   This uploads images to `gs://numista-reference-library/reference_library/user_contributed/` and writes to the index automatically.

### MANIFEST.json format
```json
{
  "contributed_by": "Eric D.",
  "contributed_date": "2026-06-20",
  "source_name": "US Mint Website",
  "license": "Public Domain",
  "attribution_text": "United States Mint image",
  "images": [
    {
      "filename": "2025_W_american-eagle-silver_obverse.jpg",
      "year": "2025",
      "mint": "W",
      "program": "american-eagle-silver",
      "side": "obverse",
      "notes": "U.S. Army 250th Anniversary privy mark"
    }
  ]
}
```

## Workflow 3 — AI Image Generation (Fallback)

**Use this when:** No reference image exists anywhere for a specific coin (confirmed after checking GCS and the index).

### Steps

1. **Confirm the gap** — run the gap report script:
   ```powershell
   .venv\Scripts\python.exe _scripts\gen_image_gap_report.py
   ```
2. **Generate images** using the Imagen pipeline:
   ```powershell
   .venv\Scripts\python.exe _scripts\coin_image_pipeline.py --year 1990 --program american-eagle-silver
   ```
3. Generated images land in `gs://numista-reference-library/reference_library/ai_generated/` and are auto-indexed as Tier 4
4. **Review the generated image** before it goes live — AI-generated coins can have hallucinated dates

> **Note:** AI-generated images are clearly tagged `"source_tier": 4` in the index. The app does not surface this label to end users currently, but it's recorded for moderation.

## Workflow 5 — User-Contributed Images (Opt-Out Consent)

**Use this when:** A user uploads a high-quality coin photo and we want to use it as a reference image for other collectors — with their permission.

### Policy
- **Default: Opted IN** — user photos that meet quality thresholds are used as reference images unless the user opts out
- **One-time popup** — shown after the first photo upload, not repeated
- **Scope** — only the coin itself (cropped/processed), never the full photo background
- **Reversible** — users can change their preference anytime in Settings → Photo Privacy
- **Attribution** — shown as *"Photo contributed by a Numista.AI member"* (never by name unless they consent)

### Quality Thresholds (Gemini Vision assessment)
| Check | Minimum |
|---|---|
| Resolution | 800 × 800 px |
| Sharpness | No motion blur |
| Lighting | Even, no harsh glare |
| Composition | Coin fills ≥60% of frame |
| Obverse/Reverse clearly identified | Yes |

### App Flow

```
User uploads photo
        ↓
Gemini Vision scores quality (async, background)
        ↓
If quality ≥ threshold AND we don't already have a Tier 1/2 image:
        ↓
Show one-time popup (first upload only):
  "Help other collectors! Your photo of the [COIN] is great quality.
   Numista.AI will use a cropped version as a reference image for others —
   no personal information is shared."
   [Got It]  [Opt Out]
        ↓
User taps "Got It" (or ignores) → preference = opted_in
User taps "Opt Out" → preference = opted_out
        ↓
Preference stored in Firestore:
  users/{email}/settings.photo_sharing_preference = "opted_in" | "opted_out"
        ↓
If opted_in:
  Image queued in coin_image_index with status = "pending_review"
  Admin reviews in Admin panel → Approve → Tier 1.5
  Moved to gs://numista-reference-library/reference_library/user_contributed/{email}/
  MANIFEST auto-generated
```

### Firestore structure for user settings
```json
{
  "photo_sharing_preference": "opted_in",
  "photo_sharing_set_at": "2026-06-20T12:00:00Z",
  "photo_sharing_popup_shown": true
}
```

## Full Rebuild Procedure

Run this when making structural changes to the index (naming convention changes, new scan targets added, stale entries):

```powershell
# From numista_backend directory:
.venv\Scripts\python.exe _scripts\build_image_index.py --wipe
```

> Takes ~20 minutes. Safe to run anytime — the app shows placeholder while the index is being rebuilt (the old index is deleted first).

For incremental updates (new images added, no structural changes):
```powershell
.venv\Scripts\python.exe _scripts\build_image_index.py
# No --wipe: merges new images, keeps existing entries
```

## Workflow 5 — User Photo Contribution (Implemented 2026-06-20)

### Flutter UI
- Upload flow: `my_collection_screen.dart` → `_onUploadVaultImage()` → Firebase Storage
- After first-ever upload: one-time opt-out popup via `_showPhotoSharingConsent()`
- Popup default = **OPT IN** (user must actively choose "No thanks" to opt out)
- Preference stored in `SharedPreferences` (local) AND `Firestore` (cross-device sync)
- Settings toggle: `Settings → Privacy & Photo Sharing` → `_buildPrivacyCard()`

### Service Layer
`lib/services/photo_sharing_service.dart`:
- `shouldShowConsent()` → true if first upload ever
- `isOptedIn()` → current preference
- `saveConsent(optedIn: bool)` → writes to both SharedPreferences + Firestore
- `syncFromFirestore()` → called in Settings.initState() for cross-device sync

### Firestore Schema
```
users/{email}/settings/photo_sharing:
{
  "opted_in": true,
  "consent_shown": true,
  "last_updated": <server timestamp>,
  "consent_version": 1
}

users/{email}/coins/{coinId}:
{
  "contribute_to_library": true,         // true = queued | "PROMOTED" = done
  "contribute_side": "obverse",
  "contribute_queued_at": "2026-06-20T...",
  "contribute_promoted_at": "2026-06-20T..."  // set by backend
}
```

### Backend Promotion Pipeline
`_scripts/promote_user_photos.py`:
- Scans all coins where `contribute_to_library == True`
- Only promotes if existing index tier >= `--min-tier` (default 3)
- Copies image to `gs://{bucket}/reference/{program_slug}/{year}_{program_slug}_{side}.jpg`
- Updates `coin_image_index` with `source_tier=1`, `source_label='user_contribution'`
- Marks coin doc as `contribute_to_library = "PROMOTED"` to prevent re-processing
- Run: `python _scripts/promote_user_photos.py --dry-run` then without `--dry-run`
